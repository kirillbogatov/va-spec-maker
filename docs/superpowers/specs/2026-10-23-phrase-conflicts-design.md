# Пересечения тренировочных фраз: дизайн

## Цель

Показать автору спецификации фразы, которые встречаются в нескольких интентах и поэтому могут путать распознавание. Отчёт справочный: он не блокирует экспорт и не влияет на пилюлю готовности.

## Область сравнения

- Берём все включённые интенты проекта (`enabled`), в том числе из разных сценариев.
- Отчёт строится для сценария: в него попадают пары, где хотя бы один интент подключён к этому сценарию.
- Выключенные интенты и пустые фразы пропускаем.
- Фразы внутри одного интента между собой не сравниваем.

## Нормализация и шаблон

1. Привести к нижнему регистру, «ё» заменить на «е», убрать пунктуацию, схлопнуть пробелы.
2. Построить шаблон: слова и словосочетания из значений и синонимов сущностей интента заменить на `{Сущность}`. Длинные совпадения заменяются первыми, поэтому «зал ожидания» не распадётся на два слова. Правило то же, что у подсветки в `IntentsPage`.
3. У каждой фразы получаются два ключа: нормализованный текст и шаблон.

Шаблоны двух интентов сравниваются по именам сущностей, а не по составу значений. Так «в спальне» у одного интента и «на кухне» у другого сходятся, если обе фразы разбираются в `{Комната}`.

## Классификация пары фраз

| Условие | Тип | Уровень |
|---|---|---|
| Совпал нормализованный текст | `exact` | ошибка |
| Не совпал текст, совпал шаблон | `template` | предупреждение |
| Шаблон состоит только из плейсхолдеров и служебных слов | `followup` | ответ на уточнение |

Служебные слова: «в», «во», «на», «для», «по», «к», «ко», «с», «со», «у», «из», «до», «за». Правило `followup` проверяется первым, поэтому дословное совпадение «спальня» у двух интентов тоже считается ответом на уточнение, а не ошибкой.

Фраза, состоящая только из значения сущности («спальня», «в спальне»), считается ответом на дозапрос всегда, независимо от того, есть ли у сценария `followup_prompt` для этой сущности. Так решил автор: проще и даёт меньше шума.

## Ядро (`core/`)

Файл `core/src/phrase-conflicts.ts` с чистой функцией:

```ts
export type ConflictKind = 'exact' | 'template' | 'followup';
export interface ConflictPair {
  kind: ConflictKind;
  phrase: string;      // фраза первого интента в исходном виде
  other_phrase: string;
  a: { id: number; name: string; scenarios: { id: number; name: string }[] };
  b: { id: number; name: string; scenarios: { id: number; name: string }[] };
}
export function findPhraseConflicts(intents: IntentForCheck[]): ConflictPair[];
```

`IntentForCheck`: id, name, фразы, подключённые сущности с их значениями и синонимами, сценарии. Функция не обращается к БД.

Эндпоинт `GET /scenarios/:sid/intents/conflicts` в `core/src/routes/intents.ts`:
1. Загрузить сценарий (404, если нет) и все включённые интенты его проекта с фразами, сущностями и сценариями.
2. Вызвать `findPhraseConflicts`.
3. Оставить пары, где хотя бы один интент подключён к сценарию `:sid`.
4. Вернуть массив пар. Для одной пары интентов возвращаются все совпавшие пары фраз, сортировка: `exact`, `template`, `followup`, затем по названиям интентов.

Сложность: индекс по ключам `Map<ключ, интент+фраза[]>`, то есть O(N) по числу фраз, а не попарное сравнение.

## Интерфейс (`web/`)

- Кнопка «Пересечения фраз» в шапке сценария рядом с `ReadinessPill`. На кнопке счётчик `exact` + `template`, если он больше нуля.
- Клик открывает диалог (`ui/dialog`) с отчётом. Данные грузятся при открытии через `api` и React Query.
- Группировка по паре интентов. Заголовок пары: названия обоих интентов, ссылки на их карточки в `/lists/intents`, метка «в этом сценарии» либо название другого сценария. Под заголовком идут строки: фраза, фраза-соперник, тип.
- Порядок групп: пары внутри сценария выше пар с другими сценариями, внутри каждой части сначала ошибки, затем предупреждения.
- Переключатель «Показать ответы на уточнения», по умолчанию выключен. Выключен: `followup`-пары не показываются и не учитываются в счётчике.
- Пустое состояние: «Пересечений не найдено».
- `buildChecks`, `buildCriteria` и экспорт не меняются.

## Ошибки

- Несуществующий сценарий: 404 «Сценарий не найден» (как в соседних маршрутах).
- Ошибка загрузки в диалоге: сообщение с кнопкой «Повторить».

## Тесты (`core/test`)

Функция `findPhraseConflicts`:
- дословное совпадение у двух интентов даёт `exact`;
- разные регистр, пунктуация и «ё»/«е» дают `exact`;
- «включи свет в спальне» и «включи свет в кухне» при общей `{Комната}` дают `template`;
- фраза-значение сущности у двух интентов («спальня», «в спальне», «на кухне») даёт `followup`, а не `exact`;
- многословные значения заменяются целиком;
- выключенный интент и пустые фразы пропускаются;
- повтор фразы внутри одного интента пары не создаёт.

Эндпоинт:
- возвращает пары для интентов этого сценария и интентов из других сценариев;
- не возвращает пары, где оба интента не подключены к сценарию;
- 404 для несуществующего сценария.

## Вне объёма

Нечёткое сходство (Жаккар, вложенность фраз), блокировка сохранения, проверка при импорте, включение в экспорт и в `buildChecks`.

## Изменение после реализации

Ответы на уточнение (`followup`) не учитываются вообще: такие пары не возвращаются эндпоинтом, переключателя «Показать ответы на уточнения» нет, `ConflictKind` содержит только `exact` и `template`. Распознавание фраз-ответов осталось в `findPhraseConflicts` и нужно, чтобы их пропускать.
