# Типы сущностей

## Цель
При создании сущности выбирается тип: строка, число, время, дата, логический (true/false). Для числа, времени и даты можно задать диапазон.

## Данные
- В `entities` добавляются колонки `type TEXT NOT NULL DEFAULT 'string'` (`string|number|time|date|boolean`), `range_min TEXT NOT NULL DEFAULT ''`, `range_max TEXT NOT NULL DEFAULT ''`. Пустая строка означает «граница не задана».
- Миграция `user_version = 2`: `ALTER TABLE ... ADD COLUMN` для баз, созданных без колонок (в `SCHEMA` колонки тоже добавляются для новых баз). Существующие сущности становятся `string`.
- Формат границ: число — десятичное (`15`, `12.5`), время — `HH:MM`, дата — `YYYY-MM-DD`.

## API (`core/src/routes/entities.ts`)
- `POST /projects/:pid/entities` принимает `type` (по умолчанию `string`), `range_min`, `range_max`.
- `PUT /entities/:id` принимает `type`, `range_min`, `range_max`.
- Валидация (400): неизвестный тип; границы у `string`/`boolean`; неверный формат границы; `min > max`. Обе границы необязательны.
- `values` сохраняются только при `type = string`; при другом типе они удаляются, границы при `string`/`boolean` обнуляются.
- `GET` (карточка и список) возвращает `type`, `range_min`, `range_max`.

## Интерфейс
- `CreateDialog` получает необязательный блок «Тип» (селект) и для number/time/date поля «от»/«до». Включается через проп, используется для сущностей: в `EntitiesPage` и при быстром создании из `ScenarioEntities`.
- Страница сущности: селект типа; для `string` — список значений и синонимов как сейчас; для number/time/date — поля диапазона (`type=number|time|date`); для boolean — подсказка «true/false». При смене типа, если есть значения или диапазон, запрашивается подтверждение очистки.
- В списке сущностей вместо «нет значений» показывается метка типа (предупреждение «нет значений» остаётся только у пустых строк).
- Переключатель «несколько значений» остаётся для всех типов.

## Экспорт и демо
- Экспорт (`model.ts`, `tables.ts`, markdown, docx): в таблицу сущностей добавляются тип и диапазон («от … до …»).
- Демо (`core/src/demo.ts`): `ROOM`, `TEMP_MODE` — строки; `TEMP_VALUE` — число 15–30 без значений; `TIME` — время, диапазон 05:00–23:00; новые `ALARM_DATE` (дата, без диапазона) и `ALARM_REPEAT` (логический) добавлены в сущности сценария «Будильник» как необязательные.
- Дамп проекта (`project-dump.ts`) должен переносить новые колонки; проверяется тестом.

## Тесты
Создание с типом; валидация диапазона и формата; очистка значений при смене типа; миграция базы без колонок; экспорт; дамп/импорт; демо создаётся.
