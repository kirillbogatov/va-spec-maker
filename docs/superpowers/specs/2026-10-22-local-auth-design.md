# Авторизация по логину и паролю (локальная)

## Цель
Закрыть интерфейс экраном входа. Пользователи и сессии хранятся в браузере, сервера нет. В меню появляется иконка профиля с выходом. Это защита интерфейса, а не данных: IndexedDB с проектами остаётся открытой для того, кто владеет браузером. Это явно сказано в README и на экране входа.

## Модель
- Роли: `admin` и `user`. Проекты общие для всех вошедших, права на проекты не различаются. Админ дополнительно управляет пользователями.
- Первый пользователь создаётся на первом запуске и становится администратором. Существующие проекты остаются на месте (они общие), перенос не нужен.
- Свободной регистрации нет: остальных заводит администратор.

## Хранение (`web/src/lib/auth.ts`)
- Отдельная база IndexedDB `va-spec-maker-auth`, хранилище `users` (ключ `id`, уникальный индекс по `login` в нижнем регистре). С SQLite проектов и JSON-экспортом не пересекается.
- Запись: `id`, `login`, `salt`, `passwordHash`, `role`, `sessionHash`, `createdAt`.
- Хеш: PBKDF2-SHA256, 310 000 итераций, случайная соль 16 байт, Web Crypto. Сравнение за постоянное время.
- Сессия: при входе генерируется случайный токен (32 байта), в запись пишется его SHA-256, в `localStorage` ключ `va-session` = `{userId, token}`. Живёт до выхода. Выход, смена и сброс пароля сбрасывают `sessionHash`; смена или сброс пароля завершает сессии других устройств/вкладок при следующей проверке.
- Валидация: логин 3–32 символа (буквы, цифры, `._-`), пароль не короче 8 символов. Ошибки на русском.
- API модуля: `hasUsers`, `createUser`, `login`, `restoreSession`, `logout`, `changePassword`, `listUsers`, `resetPassword`, `setRole`, `deleteUser`. Ограничение: нельзя удалить или понизить последнего администратора; нельзя удалить себя.

## Интерфейс
- `AuthProvider` + `useAuth()` (`web/src/hooks/useAuth.tsx`): состояние `loading | setup | anonymous | authed(user)`.
- Гейт в `main.tsx`/`App.tsx`: пока не `authed`, рендерится `AuthPage` и приложение (и `initBackend`) не загружается.
  - `setup`: «Создайте администратора» (логин, пароль, повтор).
  - `anonymous`: форма входа. Неверный логин и пароль дают одно общее сообщение. Небольшая задержка после неудачи.
- `UserMenu` (`web/src/components/UserMenu.tsx`): круглый аватар с инициалами, в выпадающем меню логин и роль, «Сменить пароль» (диалог), «Пользователи» (только админ), «Выйти». Размещается в `AppShell` внизу боковой панели на десктопе и пунктом в нижней навигации/меню на мобильном.
- «Пользователи» (диалог или страница `/users`, только админ): таблица, «Добавить», «Сбросить пароль», роль, удалить. Подтверждение через существующий `ConfirmDialog`.
- Используются существующие `ui/*` компоненты и стиль.

## Миграция
- Существующая установка без пользователей при следующем открытии показывает «Создайте администратора». Данные проектов не затрагиваются.

## Тесты (vitest, `fake-indexeddb` при необходимости)
- Хеш: один и тот же пароль даёт разные хеши с разной солью; проверка пароля.
- `createUser` валидирует логин и пароль, уникальность без учёта регистра.
- `login`: успех, неверный пароль, неизвестный логин (одинаковая ошибка).
- Сессия: `restoreSession` после `login`, недействительна после `logout` и `changePassword`.
- Последний администратор: нельзя удалить и понизить; себя удалить нельзя.

## Вне рамок
Шифрование данных, серверная авторизация, восстановление пароля без администратора (если забыл единственный админ, помогает только очистка данных сайта и импорт JSON), права на отдельные проекты, ограничение попыток входа сверх короткой задержки.
