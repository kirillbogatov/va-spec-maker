# Режим «Ключевые слова» — дизайн

Дата: 2026-10-27

## Цель

Добавить четвёртый режим описания интентов — «Ключевые слова». В нём у каждого примера фразы есть автоматически вычисляемая колонка «ключевые слова» (коды ключевых слов из справочника через запятую). Режим отражается на странице интента, в модальном окне интента на странице сценария, в предпросмотре и в экспорте (md/docx).

## Решения

- Режим — пятая настройка в «Как описывать интенты» (`IntentMode = 'phrases' | 'patterns' | 'both' | 'keywords'`), localStorage на проект, как остальные.
- В режиме `keywords` интент состоит из фраз (`intent_phrases`). Паттерны скрыты, как в режиме `phrases`, данные не удаляются.
- Колонка «ключевые слова» — **только чтение**, вычисляется по тексту фразы, в БД не хранится. При изменении справочника пересчитывается сама.
- Сопоставление — по основе слова (Snowball-стеммер `stem`). Многословный синоним совпадает как последовательность основ подряд. Код ключевого слова тоже считается синонимом. Результат: коды найденных ключевых слов в порядке появления в фразе, без повторов.
- Экспорт: колонки `Intent | Keywords | Example phrases | Entities`, фразы и ключевые слова — нумерованные списки с одинаковыми номерами.

## Справочник «Ключевые слова»

- Пункт в «Словаре проекта» (после «Зависимостей») со счётчиком; маршрут `lists/keywords/:itemId?`. Страница на `DictionaryMaster`, по образцу `DependenciesPage`. Новый вид объекта в `ObjectKind` / `TypeToken` / Command Palette.
- Поля: **код** (уникален в проекте, регистр сохраняется) и **синонимы** (список строк). Больше ничего.
- Таблица `keywords (id, project_id, code, synonyms JSON, ...)` по образцу `dependency_dictionary` (`core/src/db.ts`), `CREATE TABLE IF NOT EXISTS`. Добавить в `TABLES` в `core/src/project-dump.ts`.
- Маршруты `core/src/routes/keywords.ts`: список, создание, обновление, удаление, плюс импорт и экспорт txt. Подключить в `core/src/app.ts`. Клиент — в `web/src/lib/api.ts`.
- «Используется в» не нужно: ключевые слова не привязаны к конкретным интентам.

### txt: импорт и экспорт

- Формат: одна строка на ключевое слово, `КОД: синоним1, синоним2`. Синонимы необязательны (`КОД:` или просто `КОД`).
- Экспорт отдаёт `keywords.txt` (UTF-8), строки в порядке справочника.
- Импорт: существующие коды обновляются (синонимы заменяются), новые добавляются. Пустые строки и строки, начинающиеся с `#`, игнорируются. Дубли кодов в файле — побеждает последняя строка. Отчёт: добавлено / обновлено / пропущено. Парсер и сериализатор — чистые функции в `core`, с тестами.
- UI: кнопки «Импорт .txt» и «Экспорт .txt» в шапке справочника; скачивание через `web/src/lib/download.ts`.

## Сопоставление: общий код

Матчинг нужен и в web (по мере ввода), и в core (экспорт). Чтобы логика не расходилась, `stem.ts` и новая функция `matchKeywords(phrase, keywords)` живут в `core` (`core/src/keywords.ts` + перенос `stem`/`normalizeText`), экспортируются из `@va/core`; web импортирует их оттуда (как уже импортирует `createApp`). `web/src/lib/stem.ts` остаётся тонкой реэкспортирующей обёрткой, если на неё много ссылок, иначе импорты правятся напрямую.

## UI

- `lib/intentMode.ts`: режим `keywords` в `INTENT_MODES`, `MODE_TITLE` («Ключевые слова»…), `MODE_EMPTY`, `modeShows` (фразы да, паттерны нет), `modeKind` = `phrase`.
- `SettingsPage`: новый вариант радио-группы.
- Страница интента (`IntentsPage` / `PhrasesCell`) и модалка сценария (`IntentsTable` / `PhrasesEditor`): в режиме `keywords` каждая фраза показана строкой-таблицей с двумя колонками — «фраза» и «ключевые слова» (чипы-коды через запятую, зелёный фон как на скриншотах). Поле ввода «+ фраза» и «Добавить несколько» сохраняются; рядом с полем ввода — заглушка-колонка «ключевые слова». Колонка обновляется по мере ввода (без дебаунса, расчёт дешёвый).
- Ключевые слова загружаются запросом списка справочника (TanStack Query), общий хук `useKeywords(projectId)`.
- В строке-превью `IntentsTable` ключевые слова не выводим (остаются фразы).

## Экспорт и предпросмотр

- `parseIntentMode` принимает `keywords`; `ProjectSpec.intentMode` и `intents[]` получают вычисленное поле `keywords: string[][]` (по фразе). `buildSpec` грузит справочник и считает.
- `tables.ts` `intentsTable`: при `keywords` — колонки `[Intent, Keywords, Example phrases, Entities]`; ширины подобрать под landscape A4. `i18n.ts`: заголовки ru/en (в ru — «Ключевые слова», «Фразы для обучения»).
- Пустой набор ключевых слов у фразы — пустая строка в нумерованном списке, чтобы номера совпадали.
- md, docx и preview используют один `intentsTable`, отдельной работы не требуется.

## Учёт в смежных местах

- Подсчёт фраз в `core/src/routes/intents.ts` и `projects.ts` не меняется (режим опирается на фразы).
- Демо-данные (`demo.ts`): несколько ключевых слов, чтобы режим можно было посмотреть.
- Бэкап/восстановление: `project-dump.ts` покрывает новую таблицу.

## Тесты

- `core`: `matchKeywords` (формы слов, многословные синонимы, порядок, дедупликация, регистр, ё/е); парсер/сериализатор txt; маршруты `keywords` (CRUD, уникальность кода, импорт); экспорт `intentsTable` в режиме `keywords` (колонки и нумерация); дамп/восстановление.
- `web`: покомпонентно по существующей практике, при наличии тестов для `PhrasesCell` — режим `keywords`.

## Вне объёма

- Редактирование ключевых слов у фразы вручную.
- Хранение результата матчинга.
- Другие элементы со скриншотов (Result Codes, Relative Adj., вкладки «Логика»/«Ошибки»), которых нет в репозитории.

## Уточнения при планировании

- В БД и API поле кода называется `name` (так требует `DictionaryMaster`/`DictItem`); в UI подпись «Код». Ответ API: `{ id, project_id, name, synonyms, used_by: [] }`.
- В UI код показывается с префиксом `$` (чип `$OFF`, как на скриншотах); в БД, txt и экспорте хранится без `$`. Ведущий `$` при вводе и импорте отбрасывается.
- Код ключевого слова сопоставляется во фразе так же, как синоним.
- Пока пользователь вводит новую фразу в поле «+ фраза», средняя колонка «ключевые слова» показывает ключевые слова набираемого текста вживую.
- В экспорте фраза без ключевых слов даёт элемент списка «-» (пустой элемент нумерованного списка плохо читается в md).
