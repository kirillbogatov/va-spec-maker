# VA Spec Maker — публичная версия: дизайн

Дата: 2026-10-20. Статус: утверждён пользователем.

## Цель
Превратить внутренний сервис (Node + Express + SQLite) в публичный статический веб-приложение VA Spec Maker с live-демо на GitHub Pages.

## Отличия от внутренней версии
1. Название — «VA Spec Maker» (в шапке без префикса имени проекта).
2. Удалены справочники «Относительные регулировки» и «Result codes» и вся связанная логика:
   - роуты, страницы, пункты поиска Ctrl K, таблицы БД (`relative_adjustments`, `variant_adjustments`, `result_codes`);
   - поле «код результата» у состояний, в панели узла, в таблице переходов и в экспорте;
   - колонка «Relative adjustment» в таблице интентов;
   - вариации интента: у интента один набор фраз и сущностей (`intent_variants` и производные таблицы заменяются на `intent_phrases`, `intent_entities`);
   - весь код миграций старой БД — схема создаётся с чистого листа.
3. Несколько проектов: список на `/`, создание, переименование, дублирование, удаление, импорт/экспорт JSON; маршруты `/p/:projectId/...`; переключатель проектов в шапке.
4. Дизайн в духе Dropbox: белый фон, мало рамок и теней, один синий акцент (~#0061FE), радиусы 8–12 px, светлая боковая навигация, карточки проектов. Токены — в `web/src/index.css`.
5. Спецификации (MD и DOCX) на русском: разделы «Интенты», «Сущности», «Промпты», «Переходы между состояниями», «Ошибки»; русские заголовки колонок и служебные значения («да/нет», «(обязательно)»).
6. «Режим работы» в текущем коде отсутствует — пункт не требует работы.

## Архитектура
- Серверная часть убирается. SQLite в браузере (sql.js, WASM); БД сериализуется в IndexedDB после каждой записи (с debounce).
- Роуты `server/src/routes/*` остаются в стиле Express, но работают на мини-роутере в процессе (без HTTP) и на адаптере sql.js с интерфейсом better-sqlite3; SQL и бизнес-логика сохраняются. Код переезжает в общий пакет `core` (без Node-API), который используется и в браузере, и в тестах под Node.
- `web/src/lib/api.ts` вызывает функции `core` напрямую вместо `fetch`; интерфейс контракта для страниц сохраняется.
- Экспорт DOCX (`docx`) и MD выполняется на клиенте, файл отдаётся через Blob.
- Первый запуск: создаётся демо-проект с примером сценария. Импорт/экспорт проекта — JSON-файл.
- Деплой: GitHub Actions → GitHub Pages; Vite `base` задаётся из переменной окружения; SPA-роутинг через HashRouter (Pages не умеет fallback).
