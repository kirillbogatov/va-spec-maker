# BR-07. Критерии успеха

Измеримые критерии, глобально SM-1..SM-N. Критерии только функциональные (решение владельца продукта), проверяются демонстрацией и автотестами.

### SM-1. Полный цикл без разработчика
Аналитик за одну сессию без помощи создаёт проект, словарь, сценарий со схемой и выгружает .docx и .md. Относится к CAP-1, CAP-6, CAP-10. Проверяет UJ-1, UJ-2, UJ-3.

### SM-2. Единая правда об объектах
Правка интента или промпта, подключённого к нескольким сценариям, отражается в каждом из них и в экспорте; удаление сценария не уничтожает объекты словаря. Относится к CAP-6. Проверяет UJ-2.

### SM-3. Схема даёт однозначную таблицу
Для любой схемы без ошибок проверок таблица переходов строится детерминированно: одинаковая схема даёт идентичный порядок строк в предпросмотре, Word и Markdown. Относится к CAP-7, CAP-10. Проверяет UJ-3.

### SM-4. Проблемы видны до выгрузки
Каждая ситуация из FR-37 и FR-38 порождает замечание нужного уровня со ссылкой на место исправления. Относится к CAP-8. Проверяет UJ-3.

### SM-5. Ключевые слова считаются верно
Для набора фраз с разными словоформами, регистром и `ё`/`е` результат сопоставления совпадает с эталонным набором автотестов `core/test/keywords.test.ts`. Относится к CAP-2, CAP-5. Проверяет UJ-1.

### SM-6. Данные не теряются при переносе
Резервная копия проекта после импорта в чистый браузер даёт проект, у которого совпадают состав объектов и экспорт спецификации с исходным. Относится к CAP-11. Проверяет UJ-5.

### SM-7. Доступ ограничен
Без входа проекты недоступны; нельзя остаться без администратора (удаление/понижение последнего блокируется); смена пароля завершает чужие сессии. Относится к CAP-12. Проверяет UJ-4.

### SM-8. Работа без сети
После загрузки страницы все функции (кроме загрузки самого приложения) работают без обращений к серверу данных. Относится к CAP-14. Проверяет UJ-5, UJ-7.

### SM-9. Регрессии ловятся
Автотесты ядра и клиента (`npm test`) и сборка (`npm run build`) проходят перед публикацией на GitHub Pages. Относится к CAP-14. Проверяет UJ-7.

### SM-10. Типы сущностей работают
Сущность каждого из пяти типов создаётся и сохраняется; граница диапазона неверного формата или «от» больше «до» отклоняется; при смене типа значения очищаются после подтверждения. Относится к CAP-3. Проверяет UJ-1.

### SM-11. Промпт хранит варианты ответа
У промпта можно задать несколько вариантов ответа; пустые варианты не сохраняются; список промптов отражает наличие ответа. Относится к CAP-4. Проверяет UJ-1.

### SM-12. История и журнал различаются
Правки объектов сценария попадают в автоматическую историю по дням, повторные правки одного объекта за день склеиваются; журнал изменений заполняется вручную и выводится в документе после описания сценария, а история в документ не попадает. Относится к CAP-9. Проверяет UJ-8.

### SM-13. Поиск находит объекты проекта
Глобальный поиск по клавише «/» находит объект любого вида в текущем проекте по части названия и не показывает объекты других проектов. Относится к CAP-13. Проверяет UJ-1.
