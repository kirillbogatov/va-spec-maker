# BR-02. Возможности продукта

Возможности верхнего уровня (CAP-n): ЧТО система даёт, не КАК.

### CAP-1
- intent: Пользователь ведёт несколько независимых проектов-спецификаций.
- success: В списке проектов можно создать, переименовать, дублировать и удалить проект; содержимое проектов не смешивается.

### CAP-2
- intent: Пользователь описывает интенты голосового помощника тремя способами: тренировочными фразами, паттернами и концептами (по ключевым словам).
- success: Для интента можно ввести и найти фразы/паттерны, а выбранный режим меняет то, что показано в интерфейсе и в экспорте.

### CAP-3
- intent: Пользователь описывает сущности (параметры запросов) с типом, диапазоном, значениями и синонимами.
- success: Сущность типа «Строка» хранит значения с синонимами; «Число», «Время», «Дата» — необязательный диапазон; «Логический» — без значений.

### CAP-4
- intent: Пользователь описывает промпты — ответы ассистента (один или несколько вариантов текста).
- success: Промпт можно выбрать в переходе сценария, а его тексты попадают в спецификацию.

### CAP-5
- intent: Пользователь ведёт справочники зависимостей (параметры и проверки при запуске сценария) и ключевых слов.
- success: Зависимость с набором значений подставляется в условия переходов; ключевое слово с синонимами определяет «концепты» во фразах.

### CAP-6
- intent: Пользователь собирает сценарии из объектов проектного словаря, не дублируя их.
- success: Один интент/промпт можно подключить к нескольким сценариям; правка видна во всех, удаление сценария не удаляет объекты словаря.

### CAP-7
- intent: Пользователь строит сценарий как схему состояний и переходов (с условиями, глобальными интентами, ошибками, несколькими вкладками).
- success: Схема однозначно превращается в таблицу переходов спецификации.

### CAP-8
- intent: Система показывает, чего не хватает сценарию, и оценивает его готовность.
- success: Для сценария перечислены замечания трёх уровней (ошибка, предупреждение, сведение) со ссылкой на место исправления; в списке проекта видно число готовых сценариев.

### CAP-9
- intent: Система хранит историю изменений сценария и журнал, который можно дополнять вручную.
- success: Изменения группируются по дням, повторные правки одного объекта склеиваются, записи ссылаются на объекты.

### CAP-10
- intent: Пользователь получает готовую спецификацию в Word и Markdown, видит её в предпросмотре и выгружает схему и справочники.
- success: Документ содержит разделы «Интенты», «Сущности», «Промпты», «Переходы между состояниями», «Ошибки» и соответствует выбранному языку.

### CAP-11
- intent: Пользователь переносит данные: JSON-копия проекта, CSV справочников, txt ключевых слов.
- success: Выгруженная копия при импорте восстанавливает проект без потерь; импорт CSV обновляет существующие объекты по названию и создаёт новые.

### CAP-12
- intent: Доступ к интерфейсу защищён логином и паролем с ролями администратора и пользователя.
- success: Без входа проекты недоступны; администратор управляет учётными записями.

### CAP-13
- intent: Пользователь быстро находит любой объект проекта.
- success: Глобальный поиск по клавише «/» (палитра команд) находит интенты, сущности, промпты, зависимости, ключевые слова и сценарии.

### CAP-14
- intent: Продукт работает без сервера, данные остаются в браузере пользователя; для знакомства есть публичное демо.
- success: Приложение полностью работает в статической раздаче; демо открывается без входа, данные живут в сессии вкладки.
