# BR-05. Сценарии

Источники: `docs/superpowers/specs/2026-10-17-cui-spec-maker-design.md` (раздел «Сценарии»), `2026-10-21-unified-scenario-dictionary-design.md`, код `web/src/pages/scenarios/*`, `web/src/lib/{states,fsm}.ts`, `core/src/history.ts`.

### FR-28: Сценарий и вкладки
Сценарий — именованный конечный автомат с описанием; может состоять из нескольких вкладок (частей), у каждой своя схема. Реализует UJ-2. Относится к CAP-7.
**Проверяемые следствия:**
- Для названий новых сценариев действует префикс проекта (по умолчанию `SC_` в демо-проекте).

### FR-29: Подключение, а не владение
Сценарий подключает интенты, промпты, сущности и зависимости из проектного словаря и не владеет ими. Реализует UJ-2. Относится к CAP-6.
**Проверяемые следствия:**
- Интент/промпт можно подключить из словаря или создать новый (он попадает в словарь и сразу подключается).
- «Убрать» снимает подключение, объект остаётся в словаре.
- В шаге и состоянии выбираются только подключённые интенты и промпты.
- Удаление сценария удаляет только его подключения.
- Нельзя снять подключение или глобальность, пока в сценарии есть ссылки на объект (причина показывается пользователю).

### FR-30: Обязательность сущности
Обязательность сущности для сценария и follow-up prompt задаются в сценарии; обязательность слота внутри интента — в самом интенте. Реализует UJ-2. Относится к CAP-6.

### FR-31: Схема состояний
Переходы редактируются на схеме: состояние — узел, переход — ребро «состояние + интент + условия → следующее состояние». Реализует UJ-2. Относится к CAP-7.
**Проверяемые следствия:**
- Ребро создаётся протягиванием от узла к узлу; узел создаётся кнопкой или двойным кликом по полотну и переименовывается на месте.
- Из одного состояния по одному интенту можно уйти в разные состояния при разных условиях; параллельные рёбра допустимы.
- Первое состояние — вход, отмечается явно, его можно сменить.
- Конечные состояния — узлы без исходящих рёбер.
- Положение узлов сохраняется; пока его нет, раскладка автоматическая; есть «Разложить заново».
- Порядок исходящих рёбер состояния — приоритет проверки условий, меняется пользователем.

### FR-32: Содержимое перехода
Переход содержит интент, параметры запроса и условия; действие системы и ответ ассистента задаются у состояния, в которое ведёт переход (у строк ошибок — в самой строке). Глобальные переходы и строки ошибок могут иметь название. Реализует UJ-2. Относится к CAP-7.

### FR-33: Условия через зависимости
Условие перехода — список пунктов; пункт сравнивает значение зависимости сценария, сущности проекта или наличие ключевого слова во фразе (равно, не равно, меньше, больше); пункты объединяются по «И» либо «ИЛИ», плюс свободный текст. Реализует UJ-2. Относится к CAP-5, CAP-7.

### FR-34: Глобальные интенты
Подключённый интент можно сделать глобальным: он срабатывает из любого состояния сценария, его переходы (с условиями и приоритетом) указывают только целевое состояние. Реализует UJ-2. Относится к CAP-7.
**Проверяемые следствия:**
- Глобальность задаётся на подключении: интент может быть глобальным в одном сценарии и локальным в другом.
- Глобальные переходы показываются отдельным блоком, а не в таблицах состояний.

### FR-35: Таблица ошибок
В сценарии есть таблица ошибок (строки с порядком перетаскиванием); строка без интента означает «по любому интенту сценария». Реализует UJ-2. Относится к CAP-7.
**Проверяемые следствия:**
- Новая строка ошибки наследует состояние предыдущей.
- На схеме ошибки не показываются.

### FR-36: Предпросмотр таблиц
Вкладка «Предпросмотр» показывает таблицы спецификации сценария в готовом виде: строки упорядочены обходом от входа, внутри состояния — по порядку рёбер, затем недостижимые состояния. Реализует UJ-3. Относится к CAP-10.

### FR-37: Проверки схемы
Схема подсвечивает проблемы: недостижимое состояние; ребро без следующего состояния; пустое ребро (нет ответа, действия и цели); недетерминизм (одинаковые условия у двух рёбер одной пары «состояние + интент», либо ребро без условий перекрывает следующие); состояние без исходящих переходов (предупреждение). Реализует UJ-3. Относится к CAP-8.

### FR-38: Замечания к сценарию и готовность
Для сценария собирается список замечаний с уровнями «ошибка / предупреждение / сведение» и переходом к месту исправления. Реализует UJ-3. Относится к CAP-8.
**Проверяемые следствия:**
- Ошибка: включённый интент без фраз.
- Предупреждения: нет описания; нет интентов; зависимость без значений; у промпта нет полного ответа.
- Сведения: промпт или интент не используются в логике; у глобального интента нет глобальных переходов.
- Сценарий считается готовым, если есть описание, интенты с фразами, заполненные ответы промптов, зависимости со значениями и хотя бы один переход; число готовых сценариев видно в проекте.

### FR-39: История сценария
Система ведёт историю изменений сценария по дням с ссылками на изменённые объекты; повторные правки одного объекта за день склеиваются, добавление и удаление в один день взаимно гасятся. История очищается пользователем. Реализует UJ-8. Относится к CAP-9.

### FR-40: Журнал изменений
Пользователь вручную редактирует журнал изменений сценария; журнал входит в экспортируемую спецификацию (FR-43). Автоматическая история (FR-39) служит только для отслеживания изменений внутри сервиса и в документ не попадает. Реализует UJ-8. Относится к CAP-9.

### FR-41: Автосохранение
Правки сценария и словаря сохраняются автоматически; сводный индикатор показывает состояние сохранения. Реализует UJ-2. Относится к CAP-7.
