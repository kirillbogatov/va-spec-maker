# Критерии успеха

1. SM-10 «Типы сущностей работают» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-18 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-03-01-BE и ED-03-01-FE.
3. FR-25 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-03-01-BE и ED-03-01-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в приложении есть проект с идентификатором из пути;
   2. действие — GET /api/projects/{pid}/entities;
   3. ожидается — ответ соответствует схеме контракта; состав и порядок элементов как в BE-доке.

# Проверки БД

Операция не меняет данные в базе: проверки БД не требуются.

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Список сущностей проекта» по шагам FE-дока этой фичи;
   3. ожидается — Возвращает сущности проекта с типом, значениями и интентами, где они используются.
2. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Список сущностей проекта» по шагам FE-дока этой фичи;
   3. ожидается — Возвращает сущности проекта с типом, значениями и интентами, где они используются.
