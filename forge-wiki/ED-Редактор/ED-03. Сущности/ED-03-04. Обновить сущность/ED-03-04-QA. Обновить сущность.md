# Критерии успеха

1. SM-10 «Типы сущностей работают» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-18 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-03-04-BE и ED-03-04-FE.
3. FR-19 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-03-04-BE и ED-03-04-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует сущность с идентификатором из пути; в теле переданы 'name' = 'ENT_комната'; 'multiple_values' = false; 'type' = 'string'; 'values' = [{value: кухня, synonyms: [на кухне]}];
   2. действие — PUT /api/entities/{id};
   3. ожидается — ответ содержит обновлённые значения; повторный GET возвращает их же.
2. Пустое название:

   1. предусловие — существует сущность с идентификатором из пути;
   2. действие — PUT /api/entities/{id} с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — PUT /api/entities/{id};
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — PUT /api/entities/{id} с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Запись таблицы 'entities' обновлена:

```sql
SELECT * FROM entities WHERE id = :id;
```
