1. При получении запроса PUT /api/intents/{id} сервер должен:

   1. [Проверить на общие ошибки](<GEN-01. Обработка запросов и ошибок>).
   2. Найти в таблице 'intents' запись, где 'intents.id' = 'id':

      1. если запись не найдена → NotFoundError.
   3. Валидировать запрос:

      1. 'name' после удаления пробелов по краям не пусто, иначе BadRequestError;
      2. если в проекте есть другой интент с таким же названием без учёта регистра и пробелов по краям → DuplicateError;
      3. если для какого-либо 'entities[].entity_id' нет записи в таблице 'entities' того же проекта → BadRequestError;
      4. 'enabled' = false только если передан false, иначе true;
      5. пустые тексты в 'values' отбросить, 'kind' не равный 'pattern' считать 'phrase';
      6. если 'values' не передан → собрать список из 'phrases' и затем 'patterns'.
   4. Обновить запись в таблице 'intents': 'name', 'enabled', 'comment'.
   5. Удалить записи таблиц 'intent_phrases', 'intent_patterns', 'intent_entities' интента.
   6. Создать записи в 'intent_phrases' и 'intent_patterns' по элементам 'values', где 'position' — индекс элемента в 'values'.
   7. Создать записи в 'intent_entities' по элементам 'entities', где 'position' — индекс элемента.
   8. Записать в 'scenario_history' каждого сценария, к которому подключён интент, изменения: переименование, включение или отключение, комментарий, добавленные и удалённые фразы и паттерны, сущности и их обязательность, а также ключевые слова, появившиеся или исчезнувшие во фразах.
   9. Вернуть ответ клиенту.

## Маппинг ответа

| Параметр в API | Параметр в БД     |
|:---------------|:------------------|
| id             | 'intents.id'      |
| name           | 'intents.name'    |
| enabled        | 'intents.enabled' |
