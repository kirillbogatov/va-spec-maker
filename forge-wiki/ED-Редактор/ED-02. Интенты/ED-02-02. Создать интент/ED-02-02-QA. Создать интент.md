# Критерии успеха

1. SM-5 «Ключевые слова считаются верно» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-16 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-02-02-BE и ED-02-02-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в приложении есть проект с идентификатором из пути; в теле переданы 'name' = 'INT_включить_свет';
   2. действие — POST /api/projects/{pid}/intents;
   3. ожидается — объект создан, в ответе его идентификатор и переданные значения.
2. Пустое название:

   1. предусловие — в приложении есть проект с идентификатором из пути;
   2. действие — POST /api/projects/{pid}/intents с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — POST /api/projects/{pid}/intents;
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — POST /api/projects/{pid}/intents с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Запись создана в таблице 'intents':

```sql
SELECT id, name FROM intents WHERE id = :id AND name = :name;
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Создать интент» по шагам FE-дока этой фичи;
   3. ожидается — Создаёт пустой интент в проекте.
