# Критерии успеха

1. SM-7 «Доступ ограничен» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-4 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.
3. FR-5 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.
4. FR-6 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.
5. FR-8 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.
6. FR-9 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.

# Проверки

1. Проверка клиентского модуля без запросов к ядру:

   1. предусловие — приложение открыто в условиях, описанных в FE-доке;
   2. действие — выполнить функциональные требования ED-09-01-FE;
   3. ожидается — результат, описанный в FE-доке, без обращения к сети.

# Проверки БД

Фича работает на стороне клиента и не обращается к БД ядра напрямую: проверки БД не требуются.

# E2E (Playwright)

1. UJ-4 «Начать работу и управлять доступом»:

   1. предусловие — приложение открыто в обычном режиме, данные браузера пусты;
   2. шаги — пользователь выполняет «Вход и сессия» по шагам FE-дока этой фичи;
   3. ожидается — Клиентские модули: Вход и сессия; спека — ED-09-01-BE/FE в ED-Редактор.
