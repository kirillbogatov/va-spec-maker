1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. SM-3 «Схема даёт однозначную таблицу» — проверяется сценариями ниже: запросы к контракту и E2E.
3. FR-42 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-08-03-BE и ED-08-03-FE.
4. FR-43 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-08-03-BE и ED-08-03-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в приложении есть проект с идентификатором из пути;
   2. действие — GET /api/projects/{pid}/export с 'format' = 'docx', 'lang' = 'ru', 'intentMode' = 'both';
   3. ожидается — ответ — файл нужного формата с именем объекта; тело не пустое.
2. Недопустимый формат:

   1. предусловие — в приложении есть проект с идентификатором из пути;
   2. действие — GET /api/projects/{pid}/export с 'format' = 'pdf';
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — GET /api/projects/{pid}/export;
   3. ожидается — NotFoundError.

# Проверки БД

Операция не меняет данные в базе: проверки БД не требуются.

# E2E (Playwright)

1. UJ-3 «Проверить и выгрузить спецификацию»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Выгрузить спецификацию проекта» по шагам FE-дока этой фичи;
   3. ожидается — Формирует один документ спецификации по всем сценариям проекта в Word или Markdown.
