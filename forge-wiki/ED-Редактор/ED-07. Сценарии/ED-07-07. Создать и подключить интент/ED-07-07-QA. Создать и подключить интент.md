# Критерии успеха

1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. SM-2 «Единая правда об объектах» — проверяется сценариями ниже: запросы к контракту и E2E.
3. FR-29 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-07-BE и ED-07-07-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в проекте есть сценарий с идентификатором из пути; в теле переданы 'name' = 'INT_включить_свет';
   2. действие — POST /api/scenarios/{sid}/intents;
   3. ожидается — объект создан, в ответе его идентификатор и переданные значения.
2. Пустое название:

   1. предусловие — в проекте есть сценарий с идентификатором из пути;
   2. действие — POST /api/scenarios/{sid}/intents с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — POST /api/scenarios/{sid}/intents;
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — POST /api/scenarios/{sid}/intents с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Интент создан и подключён:

```sql
SELECT si.scenario_id, si.intent_id, si.position FROM scenario_intents si WHERE si.scenario_id = :sid AND si.intent_id = :id;
```

# E2E (Playwright)

1. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Создать и подключить интент» по шагам FE-дока этой фичи;
   3. ожидается — Создаёт интент в проекте сценария и сразу подключает его к сценарию.
