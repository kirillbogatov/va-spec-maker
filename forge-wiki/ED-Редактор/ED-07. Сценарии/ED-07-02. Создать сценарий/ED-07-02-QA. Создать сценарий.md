# Критерии успеха

1. SM-3 «Схема даёт однозначную таблицу» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-28 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-02-BE и ED-07-02-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в приложении есть проект с идентификатором из пути; в теле переданы 'name' = 'SC_свет';
   2. действие — POST /api/projects/{pid}/scenarios;
   3. ожидается — объект создан, в ответе его идентификатор и переданные значения.
2. Пустое название:

   1. предусловие — в приложении есть проект с идентификатором из пути;
   2. действие — POST /api/projects/{pid}/scenarios с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — POST /api/projects/{pid}/scenarios;
   3. ожидается — NotFoundError.

# Проверки БД

Сценарий и его первая вкладка созданы:

```sql
SELECT s.id, s.name, (SELECT COUNT(*) FROM scenario_parts p WHERE p.scenario_id = s.id) AS parts
FROM scenarios s WHERE s.id = :id; -- parts = 1
```

# E2E (Playwright)

1. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Создать сценарий» по шагам FE-дока этой фичи;
   3. ожидается — Создаёт сценарий с одной вкладкой и записью о создании в истории.
