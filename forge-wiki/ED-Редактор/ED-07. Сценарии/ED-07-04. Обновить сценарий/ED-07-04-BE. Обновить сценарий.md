1. При получении запроса PUT /api/scenarios/{id} сервер должен:

   1. [Проверить на общие ошибки](<GEN-01. Обработка запросов и ошибок>).
   2. Найти в таблице 'scenarios' запись, где 'scenarios.id' = 'id':

      1. если запись не найдена → NotFoundError.
   3. Валидировать запрос:

      1. 'name' после удаления пробелов по краям не пусто, иначе BadRequestError;
      2. в 'dependencies' каждый 'ref' не пуст и уникален в сценарии, иначе BadRequestError;
      3. 'dependencies[].type' вне перечня 'string', 'enum', 'bool' считать 'string';
      4. в 'entities' сущность не повторяется, иначе BadRequestError;
      5. каждая сущность из 'entities' и 'dependencies[].entity_id' существует в таблице 'entities' того же проекта, иначе BadRequestError;
      6. если 'parts' не передан → оставить текущие вкладки; пустой список вкладок → BadRequestError;
      7. название вкладки по умолчанию — 'name' и номер вкладки;
      8. 'kind' строки вне перечня 'error', 'global' считать 'transition';
      9. у строки с 'kind' не равным 'error' обнулить 'prompt_id' и 'system_action'; у строки с 'kind' = 'global' обнулить 'state';
      10. пункт условия по зависимости ссылается на существующий 'ref' сценария, иначе BadRequestError;
      11. сущность, ключевое слово, интент и промпт строки и состояния существуют в таблицах 'entities', 'keywords', 'intents', 'prompts' того же проекта, иначе BadRequestError;
      12. строка с 'kind' = 'global' и интентом допустима только если интент подключён к сценарию с 'is_global' = true, иначе BadRequestError;
      13. 'cond_mode' = 'any' только если передан 'any', иначе 'all'; 'op' вне перечня '!=', '<', '>' считать '='.
   4. Заменить содержимое в одной транзакции:

      1. обновить запись в таблице 'scenarios': 'name', 'description';
      2. удалить записи 'scenario_parts', 'scenario_states', 'scenario_steps', 'scenario_entities', 'scenario_dependencies' сценария;
      3. создать записи 'scenario_entities' и 'scenario_dependencies' по порядку ('position' = индекс);
      4. создать запись 'scenario_parts' для каждой вкладки с положением узлов в 'layout';
      5. создать запись 'scenario_states' для каждого состояния, у которого есть описание, промпт или действие системы;
      6. создать записи 'scenario_steps' для строк вкладки ('position' = индекс).
   5. Подключить к сценарию интенты и промпты, на которые ссылаются строки и состояния и которые ещё не подключены (записи в 'scenario_intents', 'scenario_prompts').
   6. Записать различия между прежним и новым сценарием в 'scenario_history'.
   7. Вернуть ответ клиенту.

## Маппинг ответа

| Параметр в API      | Параметр в БД                                                                  |
|:--------------------|:-------------------------------------------------------------------------------|
| id                  | 'scenarios.id'                                                                 |
| project_id          | 'scenarios.project_id'                                                         |
| name                | 'scenarios.name'                                                               |
| description         | 'scenarios.description'                                                        |
| entities[]          | строки таблицы 'scenario_entities'                                             |
| dependencies[]      | строки таблицы 'scenario_dependencies'                                         |
| parts[].name        | 'scenario_parts.name'                                                          |
| parts[].description | 'scenario_parts.description'                                                   |
| parts[].steps[]     | строки таблицы 'scenario_steps' вкладки                                        |
| parts[].layout      | 'scenario_parts.layout' (положение) и 'scenario_states' (содержимое состояний) |
