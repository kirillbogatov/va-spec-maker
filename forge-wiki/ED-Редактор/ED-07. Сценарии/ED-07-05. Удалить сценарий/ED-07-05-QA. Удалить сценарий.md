# Критерии успеха

1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. SM-2 «Единая правда об объектах» — проверяется сценариями ниже: запросы к контракту и E2E.
3. FR-3 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-05-BE и ED-07-05-FE.
4. FR-29 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-05-BE и ED-07-05-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует сценарий с идентификатором из пути;
   2. действие — DELETE /api/scenarios/{id};
   3. ожидается — ответ без тела; повторный GET того же объекта возвращает NotFoundError.
2. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — DELETE /api/scenarios/{id};
   3. ожидается — NotFoundError.

# Проверки БД

Сценарий и подключения удалены, интенты проекта остались:

```sql
SELECT (SELECT COUNT(*) FROM scenarios WHERE id = :id) AS scenarios, (SELECT COUNT(*) FROM scenario_intents WHERE scenario_id = :id) AS links; -- оба 0
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Удалить сценарий» по шагам FE-дока этой фичи;
   3. ожидается — Удаляет сценарий и его подключения; интенты, промпты и сущности проекта остаются.
2. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Удалить сценарий» по шагам FE-дока этой фичи;
   3. ожидается — Удаляет сценарий и его подключения; интенты, промпты и сущности проекта остаются.
