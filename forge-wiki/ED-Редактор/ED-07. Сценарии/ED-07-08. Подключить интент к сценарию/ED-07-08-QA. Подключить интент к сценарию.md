2. SM-2 «Единая правда об объектах» — проверяется сценариями ниже: запросы к контракту и E2E.
3. SM-3 «Схема даёт однозначную таблицу» — проверяется сценариями ниже: запросы к контракту и E2E.
4. FR-29 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-08-BE и ED-07-08-FE.
5. FR-34 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-08-BE и ED-07-08-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в проекте есть сценарий с идентификатором из пути; в проекте есть интент с идентификатором из пути; в теле переданы 'is_global' = true;
   2. действие — PUT /api/scenarios/{sid}/intents/{iid};
   3. ожидается — ответ содержит обновлённые значения; повторный GET возвращает их же.
2. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — PUT /api/scenarios/{sid}/intents/{iid};
   3. ожидается — NotFoundError.
3. Снятие глобальности при наличии глобальных переходов:

   1. предусловие — интент подключён как глобальный и есть строка с 'kind' = 'global' для него;
   2. действие — PUT /api/scenarios/{sid}/intents/{iid} с 'is_global' = false;
   3. ожидается — InUseError.

# Проверки БД

Подключение и признак глобальности:

```sql
SELECT is_global FROM scenario_intents WHERE scenario_id = :sid AND intent_id = :iid;
```

# E2E (Playwright)

1. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Подключить интент к сценарию» по шагам FE-дока этой фичи;
   3. ожидается — Подключает существующий интент проекта к сценарию; если передан is_global, меняет признак глобальности.
