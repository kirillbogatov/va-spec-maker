# Критерии успеха

1. SM-3 «Схема даёт однозначную таблицу» — проверяется сценариями ниже: запросы к контракту и E2E.
2. SM-4 «Проблемы видны до выгрузки» — проверяется сценариями ниже: запросы к контракту и E2E.
3. FR-28 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-03-BE и ED-07-03-FE.
4. FR-38 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-03-BE и ED-07-03-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует сценарий с идентификатором из пути;
   2. действие — GET /api/scenarios/{id};
   3. ожидается — ответ соответствует схеме контракта; состав и порядок элементов как в BE-доке.
2. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — GET /api/scenarios/{id};
   3. ожидается — NotFoundError.

# Проверки БД

Операция не меняет данные в базе: проверки БД не требуются.

# E2E (Playwright)

1. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Получить сценарий» по шагам FE-дока этой фичи;
   3. ожидается — Возвращает сценарий целиком: сущности, зависимости, вкладки со строками и состояниями.
2. UJ-3 «Проверить и выгрузить спецификацию»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Получить сценарий» по шагам FE-дока этой фичи;
   3. ожидается — Возвращает сценарий целиком: сущности, зависимости, вкладки со строками и состояниями.
