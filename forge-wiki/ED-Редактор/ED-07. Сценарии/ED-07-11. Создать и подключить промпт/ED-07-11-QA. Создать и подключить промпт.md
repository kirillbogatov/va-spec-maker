# Критерии успеха

1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. SM-2 «Единая правда об объектах» — проверяется сценариями ниже: запросы к контракту и E2E.
3. FR-29 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-07-11-BE и ED-07-11-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — в проекте есть сценарий с идентификатором из пути; в теле переданы 'name' = 'PRM_свет_включён';
   2. действие — POST /api/scenarios/{sid}/prompts;
   3. ожидается — объект создан, в ответе его идентификатор и переданные значения.
2. Пустое название:

   1. предусловие — в проекте есть сценарий с идентификатором из пути;
   2. действие — POST /api/scenarios/{sid}/prompts с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — POST /api/scenarios/{sid}/prompts;
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — POST /api/scenarios/{sid}/prompts с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Промпт создан и подключён:

```sql
SELECT sp.scenario_id, sp.prompt_id, sp.position FROM scenario_prompts sp WHERE sp.scenario_id = :sid AND sp.prompt_id = :id;
```

# E2E (Playwright)

1. UJ-2 «Собрать сценарий диалога»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Создать и подключить промпт» по шагам FE-дока этой фичи;
   3. ожидается — Создаёт промпт в проекте сценария и сразу подключает его к сценарию.
