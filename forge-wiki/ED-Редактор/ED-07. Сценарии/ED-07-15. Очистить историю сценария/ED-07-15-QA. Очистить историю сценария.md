# Критерии успеха

1. SM-12 «История и журнал различаются» — проверяется сценариями ниже: запросы к контракту.
2. FR-39 из BR-Бизнес требования выполняется: поведение совпадает с документами фичи.

# Проверки

1. Успешный запрос:

   1. предусловие — существует сценарий с идентификатором из пути;
   2. действие — DELETE /api/scenarios/{id}/history;
   3. ожидается — ответ без тела; повторный GET того же объекта возвращает NotFoundError.
2. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — DELETE /api/scenarios/{id}/history;
   3. ожидается — NotFoundError.

# Проверки БД

История сценария очищена, журнал остался:

```sql
SELECT (SELECT COUNT(*) FROM scenario_history WHERE scenario_id = :id) AS history, (SELECT COUNT(*) FROM scenario_changelog WHERE scenario_id = :id) AS changelog; -- history = 0
```

# E2E (Playwright)

1. UJ-8 «Разобраться, что и когда менялось в сценарии»:

   1. предусловие — нет экранов у этой операции; сквозная проверка — в E2E связанных экранов;
   2. шаги — вызов DELETE /api/scenarios/{id}/history происходит из интерфейса при выполнении сценария, описанного в E2E связанных фич раздела;
   3. ожидается — Удаляет автоматическую историю изменений сценария; журнал изменений не затрагивается.
