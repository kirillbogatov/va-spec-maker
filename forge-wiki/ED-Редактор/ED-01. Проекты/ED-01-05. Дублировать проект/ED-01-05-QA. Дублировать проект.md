# Критерии успеха

1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-1 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-01-05-BE и ED-01-05-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует проект с идентификатором из пути;
   2. действие — POST /api/projects/{id}/duplicate;
   3. ожидается — операция выполнена, ответ соответствует контракту.
2. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — POST /api/projects/{id}/duplicate;
   3. ожидается — NotFoundError.
3. Некорректный запрос:

   1. предусловие — существует проект с идентификатором из пути;
   2. действие — POST /api/projects/{id}/duplicate с нарушением проверок из BE-дока;
   3. ожидается — BadRequestError.

# Проверки БД

Копия проекта и содержимое совпадают с исходным:

```sql
SELECT p.name, (SELECT COUNT(*) FROM intents i WHERE i.project_id = p.id) AS intents, (SELECT COUNT(*) FROM scenarios s WHERE s.project_id = p.id) AS scenarios
FROM projects p
WHERE p.id IN (:source_id, :copy_id);
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Дублировать проект» по шагам FE-дока этой фичи;
   3. ожидается — Создаёт копию проекта с названием «<название> (копия)» и всем содержимым.
