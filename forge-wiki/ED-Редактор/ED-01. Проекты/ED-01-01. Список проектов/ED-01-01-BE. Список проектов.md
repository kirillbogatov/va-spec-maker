1. При получении запроса GET /api/projects сервер должен:

   1. [Проверить на общие ошибки](<GEN-01. Обработка запросов и ошибок>).
   2. Найти в таблице 'projects' все записи.
   3. Для каждого проекта посчитать:

      1. Количество записей в таблицах 'scenarios', 'intents', 'entities', 'prompts', где 'project_id' = 'projects.id'.
      2. Количество готовых сценариев — записей 'scenarios' проекта, где одновременно:

         1. 'scenarios.description' не пусто.
         2. Есть хотя бы одна запись в 'scenario_intents'.
         3. У каждого подключённого интента с 'intents.enabled' = true есть хотя бы одна запись в 'intent_phrases'.
         4. У каждого подключённого промпта 'prompts.full_answers' не равно '[]'.
         5. У каждой зависимости сценария с 'scenario_dependencies.type' не равным 'bool' поле 'scenario_dependencies.options' не равно '[]'.
         6. Есть хотя бы одна запись в 'scenario_steps' с 'kind' = 'transition'.
   4. Применить сортировку:

      1. 'projects.created_at' — DESC;
      2. 'projects.id' — DESC.
   5. Вернуть ответ клиенту.

## Маппинг ответа

| Параметр в API    | Параметр в БД                     |
|:------------------|:----------------------------------|
| []                | строки таблицы 'projects'         |
| [].id             | 'projects.id'                     |
| [].name           | 'projects.name'                   |
| [].description    | 'projects.description'            |
| [].created_at     | 'projects.created_at'             |
| [].scenario_count | число записей 'scenarios' проекта |
| [].intent_count   | число записей 'intents' проекта   |
| [].entity_count   | число записей 'entities' проекта  |
| [].prompt_count   | число записей 'prompts' проекта   |
| [].ready_count    | число готовых сценариев проекта   |
