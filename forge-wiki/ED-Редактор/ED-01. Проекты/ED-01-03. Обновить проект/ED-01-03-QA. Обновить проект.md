# Критерии успеха

1. SM-1 «Полный цикл без разработчика» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-1 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-01-03-BE и ED-01-03-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует проект с идентификатором из пути; в теле переданы 'name' = 'Умный дом 2';
   2. действие — PATCH /api/projects/{id};
   3. ожидается — ответ содержит обновлённые значения; повторный GET возвращает их же.
2. Пустое название:

   1. предусловие — существует проект с идентификатором из пути;
   2. действие — PATCH /api/projects/{id} с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — PATCH /api/projects/{id};
   3. ожидается — NotFoundError.

# Проверки БД

Запись таблицы 'projects' обновлена:

```sql
SELECT * FROM projects WHERE id = :id;
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Обновить проект» по шагам FE-дока этой фичи;
   3. ожидается — Меняет название и/или описание проекта; непереданные поля остаются прежними.
