# Критерии успеха

1. SM-5 «Ключевые слова считаются верно» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-22 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-06-04-BE и ED-06-04-FE.
3. FR-23 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-06-04-BE и ED-06-04-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует ключевое слово с идентификатором из пути; в теле переданы 'name' = 'OFF'; 'synonyms' = [выключи, погаси];
   2. действие — PUT /api/keywords/{id};
   3. ожидается — ответ содержит обновлённые значения; повторный GET возвращает их же.
2. Пустое название:

   1. предусловие — существует ключевое слово с идентификатором из пути;
   2. действие — PUT /api/keywords/{id} с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — PUT /api/keywords/{id};
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — PUT /api/keywords/{id} с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Запись таблицы 'keywords' обновлена:

```sql
SELECT * FROM keywords WHERE id = :id;
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Обновить ключевое слово» по шагам FE-дока этой фичи;
   3. ожидается — Заменяет код и синонимы ключевого слова.
