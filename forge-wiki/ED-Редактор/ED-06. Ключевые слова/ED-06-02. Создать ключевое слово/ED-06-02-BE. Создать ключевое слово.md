1. При получении запроса POST /api/projects/{pid}/keywords сервер должен:

   1. [Проверить на общие ошибки](<GEN-01. Обработка запросов и ошибок>).
   2. Валидировать запрос:

      1. 'name' без ведущего '$' и пробелов по краям не пусто, иначе BadRequestError.
   3. Найти в таблице 'projects' запись, где 'projects.id' = 'pid':

      1. если запись не найдена → NotFoundError.
   4. Найти в таблице 'keywords' запись проекта, где 'keywords.name' равно 'name' без учёта регистра:

      1. если запись найдена → DuplicateError.
   5. Создать запись в таблице 'keywords': 'project_id' = 'pid', 'name'.
   6. Определить 'used_by' — сценарии проекта, где ключевое слово:

      1. указано в условии строки сценария ('scenario_steps.conditions');
      2. найдено во фразах интента, подключённого к сценарию ('scenario_intents'), по правилам сопоставления ключевых слов.
   7. Вернуть ответ клиенту.

## Маппинг ответа

| Параметр в API | Параметр в БД                                                                                                            |
|:---------------|:-------------------------------------------------------------------------------------------------------------------------|
| id             | 'keywords.id'                                                                                                            |
| project_id     | 'keywords.project_id'                                                                                                    |
| name           | 'keywords.name'                                                                                                          |
| synonyms       | 'keywords.synonyms'                                                                                                      |
| used_by[]      | 'scenarios.id', 'scenarios.name' сценариев с условием по ключевому слову либо с интентом, во фразах которого оно найдено |
