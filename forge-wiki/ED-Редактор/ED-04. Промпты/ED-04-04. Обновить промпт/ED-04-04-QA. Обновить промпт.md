# Критерии успеха

1. SM-11 «Промпт хранит варианты ответа» — проверяется сценариями ниже: запросы к контракту и E2E.
2. FR-20 из BR-Бизнес требования выполняется: наблюдаемое поведение совпадает с ED-04-04-BE и ED-04-04-FE.

# Проверки

1. Успешный запрос:

   1. предусловие — существует промпт с идентификатором из пути; в теле переданы 'name' = 'PRM_свет_включён'; 'full_answers' = [Свет включён];
   2. действие — PUT /api/prompts/{id};
   3. ожидается — ответ содержит обновлённые значения; повторный GET возвращает их же.
2. Пустое название:

   1. предусловие — существует промпт с идентификатором из пути;
   2. действие — PUT /api/prompts/{id} с 'name' = пустая строка;
   3. ожидается — BadRequestError.
3. Объект не найден:

   1. предусловие — идентификатор в пути не принадлежит ни одному объекту (например, 999999);
   2. действие — PUT /api/prompts/{id};
   3. ожидается — NotFoundError.
4. Повтор названия:

   1. предусловие — в проекте уже есть объект с тем же названием (проверяется без учёта регистра);
   2. действие — PUT /api/prompts/{id} с тем же 'name';
   3. ожидается — DuplicateError.

# Проверки БД

Запись таблицы 'prompts' обновлена:

```sql
SELECT * FROM prompts WHERE id = :id;
```

# E2E (Playwright)

1. UJ-1 «Описать словарь проекта»:

   1. предусловие — приложение открыто в демо-режиме, открыт демо-проект «Демо: умный дом»;
   2. шаги — пользователь выполняет «Обновить промпт» по шагам FE-дока этой фичи;
   3. ожидается — Заменяет название и варианты ответа; изменение попадает в историю сценариев, где промпт подключён.
