1. Общий порядок обработки любого запроса к сервису (локальное ядро в браузере, HTTP-сервера нет — см. [AD-02](<AD-02-in-process-router>)):

   1. Принять метод, адрес и необязательное тело запроса.
   2. Скопировать тело через JSON-сериализацию, чтобы обработчик не менял исходный объект клиента.
   3. Отбросить префикс '/api' из адреса и разобрать параметры пути и строки запроса; значения параметров пути декодировать.
   4. Выбрать первый маршрут, у которого совпали метод и шаблон адреса (завершающий '/' допускается).
   5. Если маршрут не найден → NotFoundError.
2. Идентификаторы и обязательные поля:

   1. Идентификатор в адресе — целое число больше 0, иначе BadRequestError.
   2. Обязательное строковое поле после удаления пробелов по краям не пусто, иначе BadRequestError.
   3. Необязательное строковое поле, переданное не строкой, считается пустой строкой.
   4. В списках строк пробелы по краям удаляются, пустые элементы отбрасываются.
3. Формирование ошибки:

   1. Ошибка прикладной проверки возвращается с HTTP-статусом и телом из полей 'error' (код), 'message' (сообщение на русском) и 'details' (дополнительные данные, если есть).
   2. Нарушение уникальности в базе возвращается как DuplicateError.
   3. Любая другая ошибка возвращается как InternalError с сообщением «Внутренняя ошибка», подробности пишутся в консоль браузера.
4. Обработка общих ошибок в веб-клиенте:

   1. Показать пользователю уведомление с текстом 'message' из ответа.
   2. Данные формы и состояние экрана не сбрасывать.
   3. На экране автосохранения показать состояние ошибки сохранения.
